# GitCat 工作流与功能区域

## 设计目标

GitCat 的主流程按用户任务组织，而不是按底层 Git 命令堆叠。打开仓库后默认进入“变更”，完成检查、暂存和提交；“提交历史”用于追溯；“分支”用于上下文切换；“仓库洞察”只承载分析。跨仓库操作独立放入“批量任务”，避免误操作。

## 当前信息架构

| 区域 | 核心任务 | 当前能力 | 后续补充 |
| --- | --- | --- | --- |
| 仓库列表 | 发现并进入仓库 | 全盘扫描、目录扫描、筛选、批量勾选 | 最近使用持久化、收藏、状态摘要 |
| 变更 | 完成一次本地提交 | 已暂存/未暂存/未跟踪/冲突分组、文件差异、暂存、取消暂存、提交 | 分块暂存、放弃变更、提交检查、Amend |
| 提交历史 | 理解和追溯历史 | 多泳道拓扑图、搜索、引用标签、父提交、变更文件统计 | 分支/作者/日期过滤、文件 Diff、Cherry-pick、Revert |
| 分支 | 创建与切换工作上下文 | 搜索、新建并切换、切换、安全删除、保护标识 | 远端分支、Smart Checkout、比较、合并、Rebase |
| 同步 | 与远端交换提交 | Fetch、Pull、Push、领先/落后提示 | Push 预览、选择远端、冲突引导、Force-with-lease |
| 仓库洞察 | 理解仓库构成 | 语言体积、贡献者新增行估算 | 时间范围、趋势、导出 |
| 批量任务 | 对明确选中的仓库执行重复操作 | 状态、Pull、GC、逐仓库结果 | Dry-run 计划、可取消任务、持久审计 |

## 日常主路径

1. 在“仓库列表”扫描或选择工作目录，打开仓库。
2. 在“变更”中逐个检查 Diff，将相关文件放入暂存区。
3. 填写提交说明并提交；提交按钮只处理已暂存文件。
4. 在“提交历史”核对拓扑、引用和提交文件，再按需 Push。
5. 需要切换任务时进入“分支”；有会被覆盖的本地改动时由 Git 阻止切换，不做强制覆盖。

## 安全边界

- 删除分支默认使用安全删除，未合并分支会失败，不自动使用 `-D`。
- Push 需要再次确认；不提供普通 `--force`。
- 批量操作只作用于仓库列表中明确勾选的路径，不重新扫描扩大范围。
- Reset、Stash 清理、强制删除等高风险能力不放入主流程，后续应进入带预演和恢复说明的“高级工具”。

## 回归场景

- 文件名包含空格或中文时，状态列表仍能完整显示。
- 同一文件同时有已暂存和未暂存修改时，会分别出现在两个分组。
- 初始仓库、无远端仓库、Detached HEAD、合并提交均可只读打开。
- 分叉/合并历史显示多条泳道，合并提交能显示多个父提交。
- 暂存 → 取消暂存 → 再暂存 → 提交后，工作区状态正确刷新。
- 未合并分支删除失败且不丢提交；有冲突风险的切换失败且不覆盖文件。
